# 执行结果 · 2026-08-18

环境：`python3 -m http.server 8899` + Chrome（桌面 1280×720）。除注明外全部走**预览模式**
（登录页底部 Preview without an account），数据是本机 IndexedDB 的示例数据。

| 结果 | 用例号 |
|---|---|
| **F（不符合预期）** | 7, 8, 36, 47, 49, 52, 80, 81, 82, 83, 94 |
| **N（未测，原因见下）** | 4, 6, 11, 65, 98, 99 |
| P | 其余 83 条 |

## N 的原因

- **4 / 6 / 11**：需要真实 Supabase 账号密码。仓库里没有密码，预览态没有 auth session，
  所以「正确登录」「未验证邮箱」「刷新后会话恢复」都跑不了。预览态刷新回登录页是设计如此
  （`startPreview` 故意不写缓存）。
- **65**：加入申请表要填密码、会开一个新账号。我不代替你注册账号 / 输密码，这条留给你手动跑。
- **98 / 99**：预览态没有 auth session，云端每次写都被 RLS 拒（401），出站队列永远不会清空；
  多设备一致同理，需要两台设备各自真实登录。

## F 的明细

### 一、日期用 `toISOString()` 算本地日 —— 一个根因，两处伤害（52，并连累 82）

`js/util.js:14` `todayISO()` 和 `js/roster.js:42` `weekKey()` 都把**本地零点的 Date**
丢给 `toISOString()`。UTC+8 / UTC+10 会整体退一天：

- 本周 key 算出 `2026-08-16`（周日），README 写的是「周一」。
- 排班表头因此写成 `Mon 16 Aug / Tue 17 Aug / … / Sun 22 Aug` —— 16 Aug 2026 是**周日**，
  每一列的星期几都比日期早一天。周条也显示 `16 Aug – 22 Aug`。
- 员工端「TODAY」卡片今天（18 Aug 周二）显示 `17 Aug`。
- 更要命的是每日任务：墨尔本 UTC+10，早上 09:00 本地时 UTC 还是前一天，
  `todayISO()` 返回昨天 —— 整个早市看到的都是**昨天的清单**，10:00 才翻篇。

修一处即可：本地日用 `d.getFullYear()+'-'+…` 或 `toLocaleDateString('en-CA')`，
`todayISO` / `weekKey` 共用。

### 二、每日任务第二天就空了（82）

`js/seed.js:369` 只在 seed 时按 `todayISO()` 生成 5 条任务，全库没有任何按天补发的代码。
把 `todayISO` 临时改成明天再进页面，清单是 `0 / 0` —— 不是「重置为未完成」，是**一条都没有**。
需要一个「进任务页时，若今天没有任务就按模板生成」的补发。

### 三、盘点接受负数（36）

罐子详情 → 数量填 `-5` → 保存，直接入库：货架显示 `-5 pairs left`，
总值把 −$0.20 也算进去。没有任何校验或钳制。

### 四、要照片的任务不需要照片（80）

任务记录里根本没有「需要照片」这个字段（`id,name,date,done,photo,by,…`）。
名字叫 `Closing fridge stocktake photo` 的任务，不拍照直接打勾就完成，`photo: null`。
对比收货那边做得很对：短少/损坏的行不传照片就拦住（48 P）。

### 五、温度只存不看（81、47）

- 冰箱温度检查填 `18°C`：照样完成，**不产生任何提醒**（预期是提醒但不阻断）。
- 收货填冷藏 `12°C`：`js/deliveries.js` 只把 `tempC` 存下来、详情页显示，全文没有任何阈值判断。

### 六、老板/经理在「列表」视图勾不动任务（83）

`js/views/manager.js` 的列表把 `.task-check` 画出来了，但**没有绑任何点击处理**
（员工端 `staff.js` 绑的是 `data-tk`）。点了没反应、不报错。
走「厨房」工位视图可以勾（`kitchen-game.js` 有 `data-row` 处理），会留痕 `by: James Carter`。
所以功能在，列表视图是死的。

### 七、登录页两条（7、8）

- **7**：用户名密码都空点登录，照样发一次 `POST /auth/v1/token` 到 Supabase，
  然后返回「Wrong username/email or password」。缺一个非空判断。
- **8**：断网登录，按钮能恢复（好），但提示还是「Wrong username/email or password」。
  `js/auth.js:73` 只区分了 confirm 一种情况，网络错误被当成密码错。

### 八、i18n（94）

- **`"Password"` 这个 key 在字典里出现两次**：`js/i18n.js:304` 是 `密码`，
  `js/i18n.js:930` 是 `修改密码`（给侧栏改密码按钮用的）。后者覆盖前者，
  于是**登录页的密码输入框标签变成「修改密码」**。zh-Hant 同病（`js/lang/zh-Hant.js:272 / 898`）。
- 没有译文的可见文案：侧栏 `Add people` 及其页标题、预览横幅整句、
  同步小药丸 `Saving N changes…`、设置页品牌色那段说明、登录页 `Forgot password?` 与 demo 账号那行。

### 九、收货没有手写签名（49）

表单里是「Received by」文本框，全 `js/deliveries.js` 没有 canvas / 签名板，
日志写「signed Maria Lopez」其实是打字打进去的名字。README 里「photo, signature」这句需要改，
或者补一个签名板。

## 顺手发现的（不在 100 条里）

- **提醒会重复**：`js/alerts.js` 的 raise() 先读后写做去重，仪表盘并发调用时全部读到旧值，
  于是同一个 `key`（如 `noshow-s3`）能同时存在两条未读。跑几轮下来 15 条里 7 条是重复的。
- **角标只在切页时刷新**：新建待收货后当前页角标不动，跳一次页才出现。
- **弹窗打开时背景还能滚**：罐子详情打开后滚动，滚的是后面的页面。

## 已验证没问题的重点（挑几条）

- 金额：数量 × 单价两位小数处处对得上（3334.9 × $0.04 = $133.40，15 kg × $19.60 = $294.00）。
- 用量预测把算式摊开给你看：`0.6 + 4 − 2.32 = 2.28 / 7 天 = 0.33 一天`，覆盖天数非负。
- TFN：员工自填、ATO 校验位挡掉假号、`tfnEnc` 加密存、默认掩码、老板揭示写审计
  （`tfn.view · Viewed the stored tax file number for Amy`，不含号码）、经理无任何入口。
- 供应商分享链接：`order.html#d=<base64>`，payload 在 hash 里不上服务器，打开只见那一单。
- 深色：@media print 强制回浅色，小票在深色下仍是白纸（`rgb(255,253,247)`）。
- Logo 取色：传一张纯蓝图，`--accent` 从 `#E08050` 变 `#1B4FA8`，全局跟着变，还给了对比度读数。
- 离线：断网改库存立刻本地生效、出站队列 +1；断网收货照样入库（14.76 → 19.76 kg）、队列 +5。
- 分店隔离：切到 Southbank，`stock.items()` 返回 0，本地 9 条 Melbourne 记录被 kitchenId 挡住。

跑完后已 `MKR.seed.reset()` 复位示例数据，并清掉测试期间写的主题 / 语言 / 品牌色偏好。
